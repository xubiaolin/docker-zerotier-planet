# 部署、运行与发布审计整改

基于提交 `1293ced` 的全仓库审计，修复安装、升级、管理界面以及镜像发布问题。目标环境为一台 Linux Docker 主机上的单实例，支持现有目录和挂载布局。

## 管理界面与凭据

- 新装时管理端口只发布到宿主机回环地址。本机代理或 SSH 隧道可用于远程管理。ZeroTier 通信和文件分发保持原有的监听用途。
- 新装生成随机管理员密码。容器内的 `node /app/admin-password.js initial` 由管理员领取首次密码，待领取文件仅允许部署用户通过 Docker 访问。重置生成随机密码，并保留其他管理账号。升级沿用已有密码文件。
- 登录校验失败或凭据后端报错时，Web 进程返回相应错误，ZeroTier 与下载服务继续运行。测试包含一次真实管理员登录。

## 安装、迁移与卸载

- 安装成功以容器服务通过健康检查且宿主机端口实际发布为条件。初装遇到端口占用时，管理员可在重试时修正端口。已有签名材料、节点身份、网络和授权应继续沿用。
- 原地升级沿用原容器支持的端口协议、宿主机监听地址和端口。预检在停服前识别无法重建的绑定。回滚恢复容器和数据后应结束升级记录，原服务健康异常另行报告。
- 普通 Docker 管理员可以在数据完整时重新创建丢失的容器，并在确认后删除受支持布局中的部署数据。数据操作限定于经核实的部署目录。部署菜单移除 CentOS 7 主机内核升级。
- 读取历史配置时接受合法的十进制前导零端口，并按数值检查冲突。拒绝带接口范围后缀或未指定的通告地址。健康检查只探测当前节点生成的文件。

## 构建与发布

- 管理界面依赖使用提交到仓库的锁文件。最终产物包含适用的上游许可和声明。
- CI 构建并验证 `linux/amd64` 和 `linux/arm64`，正式标签由通过验证的镜像生成。正式 Docker Hub 路径与安装入口一致，由维护者按上游条款授权发布。移除旧的独立推送脚本。
- 发布前仍可依据源代码本地构建，也可为安装菜单指定已验证的镜像。中英文部署文档给出回环访问、凭据领取、升级和发布方式。

## 验收

本地运行容器初始化、四种存储布局的升级和回滚、旧客户端连接的端到端测试。增加针对管理登录、端口冲突、保留绑定和恢复的回归检查。验证工作流及镜像许可文件。执行实际推送需要维护者的仓库凭据与分发权限。
